# design-system-by-blue

> **스킬 목표:** "나만의 디자인 스타일을 파일로 저장해두고, 언제든 불러서 PPT·문서·위젯에 적용하는 스킬"
> **파일 구조:** SKILL.md(라우터) + modules/ + references/ + scripts/
> **핵심 원칙:** 결과물은 show_widget 우선. 외부 파일은 명시적 요청 시에만. 모호한 입력도 막지 않고 Claude가 채운다.

---

## 진입점 감지 규칙

사용자의 발화를 분석하기 전, 먼저 아래 사전 감지를 실행한다.

### 사전 감지 ① — Claude Design 패키지 (.zip)

**.zip 파일이 첨부된 경우 → 진입점 ①/② 판단 없이 즉시 `modules/load.md` (Type 3) 로 직행.**

- 발화 예시: "이걸로 디자인 시스템 만들어줘", "Claude Design에서 받은 거야", "zip 파일 써줘" 등
- zip 파일만 있고 발화가 없어도 동일하게 처리
- Type 3 진입 후 load.md에서 Claude Design 패키지 여부를 최종 확인

> zip 파일을 업로드하는 행위 자체가 명확한 의도 신호. "뭐 하려고요?" 같은 재확인 불필요.

### 사전 감지 ② — 쇼케이스 직접 요청

**아래 발화 유형별로 즉시 해당 모듈로 직행한다. 진입점 ①/② 판단 불필요.**

| 발화 예시 | 이동 대상 |
|----------|----------|
| "디자인 가이드 만들어줘", "브랜드 가이드 만들어줘", "ShowCase A 만들어줘", "쇼케이스 A" | `modules/showcase_a.md` |
| "썸네일 만들어줘", "썸네일 이미지 만들어줘", "카드 이미지 만들어줘", "ShowCase B", "쇼케이스 B" | `modules/thumbnail.md` |
| "쇼케이스 만들어줘", "ShowCase 만들어줘", "상세 가이드랑 썸네일 다 만들어줘" | AskUserQuestion(ShowCase A — 상세 가이드 / ShowCase B — 썸네일 / 둘 다) → 해당 모듈 실행 |

- 모든 경우 bds_ 파일 탐색부터 시작 (modules/common.md 참조)
- 탐색 결과에 따라 파일 선택 또는 신규 생성 안내

사용자의 발화를 분석해 진입점 ①(관리) 또는 진입점 ②(적용) 중 하나로 라우팅한다.

### 진입점 ① — 디자인 스타일 관리 (생성 / 수정)

트리거: "만들어줘", "수정해줘", "바꿔줘", "필요해", "디자인 시스템", "스타일 만들고 싶어" 등

진입 후 의도에 따라 A / B / C 세 갈래로 분기한다.

```
진입점 ①
    │
    ├── A. 명확한 신규 ("새로 만들어줘")
    │        ├── A-1. 참고 파일 없음 → modules/create.md 로드 (Step 1-a부터)
    │        └── A-2. "새로 만들어줘" + 파일 첨부/경로 언급 동시에 있을 때만 진입
    │                 → modules/load.md로 색·폰트 추출 (Type 2 방식)
    │                 → 추출 결과를 Step 1-a/1-b 추천값으로 제시
    │                 → 사용자 확인·수정 후 modules/create.md 진행
    │
    ├── B. 명확한 수정 ("수정해줘", "바꿔줘")
    │        ├── B-0. 파일명 명시 시 → 탐색 없이 해당 파일 바로 로드 → modules/update.md
    │        └── 파일명 미명시 시 → 작업 폴더 bds_ 탐색 (modules/common.md)
    │               ├── 1개 → modules/update.md
    │               ├── 여러 개 → AskUserQuestion(파일 선택) → modules/update.md
    │               └── 0개 → common.md AskUserQuestion 3지선다
    │                           ├── 새로 만들기 → modules/create.md
    │                           ├── 다른 폴더에 있어요 → 경로 입력 → 로드 → modules/update.md
    │                           └── 파일 올려줄게요 → 업로드 대기 → 로드 → modules/update.md
    │
    └── C. 애매한 경우 ("필요해" 등)
             → "있어요? 없어요?" + 작업 폴더 bds_ 탐색 (modules/common.md)
               ├── 1개 → AskUserQuestion("신규? 수정?")
               │           ├── 신규 → modules/create.md
               │           └── 수정 → modules/update.md
               ├── 여러 개 → AskUserQuestion("신규? 아니면 어떤 거 수정?")
               │               ├── 신규 → modules/create.md
               │               └── 수정(파일 선택) → modules/update.md
               └── 0개 → common.md AskUserQuestion 3지선다
                           ├── 새로 만들기 → modules/create.md
                           ├── 다른 폴더에 있어요 → 경로 입력 → 로드 → 의도 확인 → update.md 또는 create.md
                           └── 파일 올려줄게요 → 업로드 대기 → 로드 → 의도 확인 → update.md 또는 create.md
```

### 진입점 ② — 디자인 스타일 적용

트리거: "내 스타일로 PPT 만들어줘", "디자인 적용해서 만들어줘", "저번 디자인으로 해줘" 등

→ modules/apply.md 로드

```
진입점 ②
    │
    ▼
같은 대화에서 방금 생성/수정한 경우?
    ├── Yes → 토큰 데이터 이미 메모리에 있음 → 파일 탐색 없이 바로 적용 실행
    └── No  → 작업 폴더 bds_ 탐색 (modules/common.md)
               ├── 1개 → 바로 적용
               ├── 여러 개 → "어떤 스타일 쓸까요?" → 선택 후 적용
               └── 0개 → common.md AskUserQuestion 3지선다
                           ├── 새로 만들기 → modules/create.md → 완료 후 apply 실행
                           ├── 다른 폴더에 있어요 → 경로 입력 → 로드 → apply 실행
                           └── 파일 올려줄게요 → 업로드 대기 → 로드 → apply 실행
```

## 공통 원칙

### 사용자 대면 언어
기술 용어 대신 일상어를 사용한다.

| 기술 용어 | 사용자 언어 |
|-----------|------------|
| 디자인 시스템 | 내 디자인 스타일 / 브랜드 설정 |
| 디자인 토큰 | 색깔·폰트 설정 |
| bds_[이름].md | 내 스타일 파일 |
| Primary 컬러 | 메인 색깔 |
| Accent 컬러 | 포인트 색깔 |
| Typography | 글꼴 |
| Border Radius | 모서리 둥근 정도 |

> 단, 파일명·모듈·reference 내부에서는 기술 용어 그대로 사용.

### 파일 처리 원칙

**파일명 규칙**
- 형식: `bds_[이름].md`
- 기본값: `bds_1.md` (두 번째부터 `bds_2.md`, `bds_3.md`...)
- 스타일 이름 → 파일명 변환 규칙:
  - 영문·숫자: 소문자로, 그대로 유지
  - 한글: 그대로 유지
  - 공백: 제거
  - 특수문자(`-`, `#`, `@`, `.` 등): 제거
  - 예: "DS - Blue 2" → `bds_blue2.md` / "내 브랜드 #1" → `bds_내브랜드1.md`

**저장 위치**
- 고정 경로 없음. 저장 전 "어디에 저장할까요?" 한 번 확인.
- 기본 제안: 현재 대화 작업 폴더

**버전 백업 (Undo 1단계)**
- 수정 시: 현재 파일 → `bds_[이름]_prev.md`로 이름 변경 → 새 버전을 `bds_[이름].md`로 저장
- 항상 최신 + 직전 버전 두 개만 유지. 그 이전은 없어짐.
- "이전으로 돌려줘" 요청 시 `_prev` 파일을 현재 버전으로 복원
- 예: `bds_blue.md` (현재) + `bds_blue_prev.md` (직전)

**불러오기 방법 (Type 1·2 공통)**
- 방법 A: 파일 업로드
- 방법 B: 경로 입력 → Claude가 Read로 읽어옴
- 방법 C: 텍스트를 채팅에 직접 붙여넣기
- `bds_` 프리픽스가 있으면 우리 포맷(Type 1)으로 자동 판별

### 결과물 출력 원칙
- show_widget 우선 — 대화창 안에서 바로 보여줌
- 외부 파일(.pptx, .docx 등) 생성은 사용자가 명시적으로 요청할 때만

### 중복 인터뷰 방지 (P5)
- 같은 대화 안에서 bds_ 파일이 이미 로드·생성된 상태라면, 파일 탐색이나 "어떤 스타일 쓸까요?" 같은 질문을 다시 하지 않는다. 메모리에 있는 토큰 데이터를 그대로 사용한다.

### 우아한 실패 (P6)
- bds_ 파일 탐색 결과 0개일 때: 없다고만 하지 말고 common.md의 3지선다 안내로 이어간다.
- 파일 읽기 실패(경로 오류, 권한 등): "파일을 읽지 못했어요. 경로를 다시 확인해주시거나 파일을 직접 올려주세요." 한 줄로 안내 후 대기한다. 추측으로 진행하지 않는다.
- 모듈 파일 로드 실패: 해당 모듈의 핵심 흐름을 인라인으로 요약해 최소한의 진행을 유지한다.

### 왕복 방지 (P7)
- 같은 단계에서 필요한 정보가 여러 개라면 AskUserQuestion 한 번에 묶어서 묻는다. 한 가지 물어보고 답 받고 또 한 가지 물어보는 식의 핑퐁을 피한다.
- 모듈 진입 전 이미 확정된 정보(분위기, 파일명 등)는 재확인하지 않고 그대로 사용한다.
